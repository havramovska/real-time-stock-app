### High-level architecture

### Key design patterns in use

- Repository pattern: `StockRepository` implements domain interface to hide data source details and compose adapters/mappers.
- Use Case (Application Service) pattern: `GetMultipleStockQuotesUseCase` orchestrates domain flows; Effects call it.

- Adapter/Mapper: `StockAdapter` (API → UI DTO), `ApiToDomainMapper` (API → domain entity).
- Facade over NgRx: `StockNgRxService` wraps selectors and dispatchers to decouple components from store details.
- Entity normalization: NgRx Entity Adapter provides stable IDs and sorting for `StockQuote`.
- Observer/Pub-Sub: WebSocket server pushes updates; frontend `StockWebSocketService` subscribes and emits updates to observers.

### Why it’s structured this way
- Swap data providers easily: Injection tokens + interfaces let the app run against Finnhub or a mock without UI changes (useful for local dev, CI).
- Testability and maintainability: Clean separation between `domain`, `data`, and `presentation` minimizes coupling, eases unit testing.
- Scalability with Nx: Monorepo supports multiple apps, cached builds, and shared libraries as the project grows.
- Deterministic UI state: NgRx centralizes state with serializable changes and tools like DevTools for debugging.

### Angular architecture and component model
- Q: How is the app layered (`core`, `domain`, `data`, `presentation`) and why?
  - A: `core` holds shared services/constants, `domain` defines entities/repositories/use-cases, `data` implements I/O (API/WebSocket) plus mappers/adapters, and `presentation` contains components, NgRx store, and a facade. This separation enforces clear boundaries, easier testing, and replaceable infrastructure.

- Q: Why use standalone components (e.g., `DashboardComponent`) instead of NgModules?
  - A: Standalone components reduce module boilerplate and improve tree-shaking and feature encapsulation. They play well with route-level code-splitting via `loadComponent`.

- Q: Where should cross-cutting concerns like logging and theming live?
  - A: In `core` (e.g., `LoggerService`, `ThemeService`) and optionally via interceptors/providers at the app root (`app.config.ts`). Keep usage at the edges to avoid leaking concerns into `domain`.

### Dependency Injection and providers
- Q: Why use tokens like `STOCK_REPOSITORY` and `STOCK_API_SERVICE`?
  - A: Tokens decouple interfaces from implementations, enabling easy swapping (real vs mock), better testability, and clear architecture boundaries.

- Q: How would you swap `FinnhubApiService` for a mock?
  - A: Change the provider for `STOCK_API_SERVICE` (e.g., `useClass: MockApiService`) in a dev-only module/provider set, or conditionally provide based on `environment`.

- Q: Where should `provideStoreDevtools` be registered?
  - A: In `app.config.ts`, but guarded so it’s only added in dev (e.g., `if (!environment.production) provideStoreDevtools(...)`) to avoid performance and security issues in prod.

### Clean Architecture and repositories/use-cases
- Q: Why a repository interface in `domain` and a concrete repo in `data`?
  - A: It isolates domain rules from transport/storage details, allows mocking in tests, and preserves the domain when external APIs change.

- Q: What is the role of a use-case (e.g., `GetMultipleStockQuotesUseCase`)?
  - A: It orchestrates application logic as an explicit operation boundary, keeping async/infra concerns in `data` and leaving `presentation` thin.

- Q: How do you keep domain models insulated from API changes?
  - A: Use mappers to convert API DTOs to domain entities and ban API types from leaking into `domain` or `presentation`.

### NgRx store, effects, and selectors
- Q: Why NgRx Entity Adapter here?
  - A: It normalizes `StockQuote`s by `symbol`, provides efficient CRUD helpers and memoized selectors, and reduces manual reducer code.

- Q: What’s wrong with `Set<string>` in NgRx state?
  - A: `Set` isn’t serializable, breaking DevTools/time-travel and rehydration. Prefer arrays or a string map and derive sets in selectors.

- Q: Effects vs services/facades for side effects?
  - A: Effects are ideal for action-driven async flows that update store state; facades abstract store usage for components. Keep I/O orchestration in Effects to retain a single source of truth.

### RxJS and async orchestration
- Q: Why prefer `forkJoin` over manual subscription in `getMultipleQuotes`?
  - A: `forkJoin` waits for all complete (one-shot), `combineLatest` emits on any change (continuous), `zip` pairs emissions by index.

- Q: When to use `mergeMap` vs `concatMap` vs `switchMap` in Effects?
  - A: `mergeMap` for concurrent work, `concatMap` to serialize tasks, `switchMap` to cancel stale work (e.g., responding to rapid repeated actions).

- Q: How should you handle transient API errors?
  - A: Use retry/backoff strategies (`retry`, `retryWhen` with jitter), categorize errors, and emit a failure action after exhausting attempts.

### API, adapters, and mappers
- Q: Why both `StockAdapter` and `ApiToDomainMapper`?
  - A: Adapter builds UI-friendly DTOs; mapper builds domain entities. If both paths exist, ensure they’re intentional; otherwise consolidate to a single mapping layer to reduce drift.

- Q: Where should timestamp normalization occur?
  - A: In one mapping boundary (preferably API→domain) to convert epoch seconds→milliseconds consistently, then keep `Date` objects within domain.

- Q: How do shared models in `libs/models` help?
  - A: They provide type safety at boundaries and reduce duplication, but should be limited to contracts, not domain rules.

### WebSocket client integration
- Q: How should WebSocket updates integrate with NgRx?
  - A: Stream messages through an Effect that maps to `updateStocks` actions. Use the facade for component-friendly APIs, but keep state updates via actions.

- Q: How do you keep “active” state in sync with the server?
  - A: Add an Effect that listens to `toggleStockActive` and calls `stockWebSocketService.toggleStock`, and relies on subsequent server `stock-update` to update store.

- Q: How to implement reconnection/backoff?
  - A: Use exponential backoff with jitter, max cap, and a health-check ping/pong. Gate reconnection on network online events.

### Environment/config and secrets
- Q: How should secrets be handled?
  - A: Never commit API keys. Use environment variables, a runtime config endpoint, or injected build-time variables with per-env files excluded from VCS.

- Q: Dev/prod URL management?
  - A: Drive from runtime config and match backend `PORT`; document expected values and fallback host/port detection.

- Q: How to inject runtime config without rebuilds?
  - A: Serve a `/config.json` (or similar) file and load it before app bootstrap, providing values via an `InjectionToken`.

### Performance and change detection
- Q: What change detection strategies fit real-time updates?
  - A: Use `OnPush`, `trackBy`, avoid recreating arrays/objects in templates, and split large lists into virtualized components if needed.

- Q: How to avoid over-rendering with NgRx?
  - A: Use granular memoized selectors and push pipes; avoid selecting broad state in components.

- Q: Any other optimizations relevant here?
  - A: Batch updates, throttle UI rendering (if needed), and keep pure pipes for formatting.

### Nx monorepo and tooling
